# 数据基准 v1

基准标识：`SMAT2022-SMT2020-LVHM_E-v1`。冻结日期：2026-09-30。

## 选定的主数据

生产数据采用官方 SMT2020 Release 1.0 包中的 **General Data / dataset 4 / LVHM_E**。空间运输数据采用作者 SMAT2022 仓库提交 `a6df7fef99745fa49cf347306abaeb4b19002169` 中的 **dataset 4 / LVHM_E**。

这是低产量、多品种、含工程批的生产—OHT 数据组合。完整保留 10 条生产路线、3 条工程路线、105 个加工设备组、1,068 台加工设备以及全厂路网和 500 辆 OHT。主基准不截短工艺路线、不删工程批、不裁剪有向轨道。

官方源包： https://p2schedgen.fernuni-hagen.de/fileadmin/ess/uploads_p2schedgen/SMT2020/SMT2020.zip

空间运输仓库： https://github.com/kwoo-lee/SMAT2022

原始 ZIP、Excel 和说明文档保持原样；版本、大小和 SHA256 记录在 `manifest.json`。官方包还包含其他三个场景和 AutoSched 工具格式，它们保留作参照，当前不作为额外主基准。

## 冻结规则

1. **设备映射**：104 个物理设备组同名直接映射；`DefMEt_FE_118 → DefMet_FE_118` 为唯一显式别名。所有 105 组的设备数量逐组一致。
2. **虚拟资源**：生产表的 `Delay_32` 有 400 个虚拟资源，不作为加工设备，与 1,068 台物理机台分开统计。路线中相关步骤原样保留并标注 `_is_virtual_stage`；之后须解释为缓冲行为，不能默默删掉其时间或容量影响。
3. **释放输入**：选用 `Lotrelease - variable due dates` 的 167,129 条生产批事件，及 `Lotrelease - Engineering` 的 33,438 条工程批事件。时间覆盖 2018–2025，为数据中的仿真日历，非当前实际生产订单。`Lotrelease` 汇总表用于解释流类型，不能再次展开叠加，否则会重复投片。
4. **工程路线修正**：工程释放表原始路线名为 Product_1/2/3；依据同工作簿 `Lotrelease` 汇总表和同官方包 AutoSched `part.txt`，映射至 E1/E2/E3。派生工程 CSV 保留 `_raw_route_name`、源表、源行。普通 Product_1/2/3 批不改路线。
5. **事件身份**：每个释放事件有稳定 `_event_id`。全部策略读取同一份固定输入；需求扰动必须另建场景版本。实验仿真时长可以筛选时间窗，但不能随意循环八年输入，周期复制必须另行定义交期与时间规则。
6. **源行与列**：忽略仅有格式、没有值的空行。原始 Excel 可能显示百万行，不能视为百万条记录。路线重复列名 OFFSET 按出现次序保存为 OFFSET 与 OFFSET__2，分别对应加工时间和 setup 分布参数。
7. **初始状态**：本基准未合并 AutoSched 的 WIP。初始设备、在制品状态和暖机安排属于下一阶段仿真配置，不能声称已复现作者稳态结果。数据基准本身不规定实验时长或训练集划分。

## 单位与字段解释

内部接口统一使用秒、米、wafer 数；源数据保留原单位，加载时转换，并记录来源。

| 字段 | 基准解释 | 证据或状态 |
| --- | --- | --- |
| 加工、setup、维护、故障、CQT 时间 | 根据各列单位转换；min×60、hr×3600、day×86400 | SMT2020 generic 文档及源单位列 |
| PROCESSING UNIT | Wafer / Lot / Batch 分别解释 | 不能统一按 lot 乘25，也不能把 batch 时间乘 lot 数 |
| BATCH MINIMUM/MAXIMUM | wafer 数 | generic 文档明确；工程 lot 为1–10 wafer，按实际数量合批 |
| PROCESSINGTIME DISTRIBUTION=uniform | MEAN±OFFSET | generic 文档均值与偏移；采样实现另行测试 |
| CQT | 当前工序加工结束至指定目标工序加工开始 | 目标不一定是紧邻工序；运输和排队都会消耗窗口 |
| OHT MAX_SPEED | 1500 mm/s → 1.5 m/s | SMAT generic 文档及工作簿 |
| OHT ACCELERATION/DECELERATION | 2000/3000 mm/s² → 2/3 m/s² | 同上；不能用论文值覆盖工作簿 |
| 坐标、尺寸、DISTANCE | 保留原数值；拟按mm解释时必须标明假设 | 空间单位需进一步确认，尚未授权为已验证事实 |
| Rail.MAX_SPEED | 原值全部1，保持原样 | 单位与含义待确认；不擅自作为mm/s或倍率使用 |
| PortType.SIZE | 原始几何/规格字段 | 不解释为存储容量；装卸时间与容量需另定义 |
| CURVE | 曲线标记，保留原值 | 不把端点弦长当作精确弧长 |
| Transport | 源均值7.5、偏移2.5分钟的抽象搬运 | OHT显式运输场景不再叠加5–10分钟延迟；抽象运输对照可单独保留 |

## 可复现产物

- `manifest.json`：原始来源、版本、文件哈希、转换规则和待确认语义。
- `toolgroup_mapping.csv`：全部106条生产设备组记录，其中一条为虚拟资源。
- `route_operations.csv`：13条完整路线的有值工序记录，保留原字段及来源。
- `production_release.csv`：固定逐批生产释放计划及交期。
- `engineering_release.csv`：固定逐批工程释放计划、交期及路线映射证据。
- `audit.json`：表结构、记录统计、设备数量、路线引用、重入流和释放输入核查。
- `verification.json`：独立验证结果。

复现生成命令：在项目根目录运行 `python 04-研究/freeze_data_baseline.py`，依赖 openpyxl，仅读取原始工作簿。验证命令：`python 04-研究/verify_data_baseline.py`，不重建 manifest，只读核验来源和派生文件。冻结后不要通过重建 manifest 来掩盖文件修改；任何来源或转换规则变更应创建新版本。

## 本次完成范围

已确定并冻结数据来源、主场景、完整输入、设备映射、工程路线修正与单位解释边界。数据基准已可用于后续加载器开发。

**仿真运行语义尚未就绪**：空间单位、轨道速度、曲线几何、OHT装卸时间、ZCU实现、缓冲行为、级联装卸重叠、故障中断处理仍需在仿真建模阶段落实。正式性能实验必须先完成这些规则及验证，不能将数据完整性核查当作仿真正确性证明。
