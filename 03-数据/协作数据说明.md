# 协作数据准备

2026-10-13。Git随代码提供运行必需的数据，原始文件保持只读。

## 克隆后运行

仓库包含SMAT2022和SMT2020的dataset 4 / LVHM_E两份工作簿，以及`基准-v1/`下的`toolgroup_mapping.csv`、`route_operations.csv`、`production_release.csv`、`engineering_release.csv`。它们保留冻结字节，SHA256沿用`基准-v1/manifest.json`。无需Git LFS或额外下载。

在仓库根目录用PowerShell执行：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev,transport,sumo-tools]"
.venv\Scripts\python.exe scripts/verify_collaboration_data.py
.venv\Scripts\python.exe -m fabcosim demo --config configs/smat_two_tools.json
```

完整工艺使用`fabcosim full`，持续投片使用README列出的配置。数据齐备不等于完整基准的全部运行语义均已验证；实现范围仍以README和开发记录为准。

## 完整来源复核

协作核验脚本只检查上述六份输入，不覆盖完整上游包。历史`verification.json`是已有核验记录，不代表新克隆已经执行完整来源核验。

完整上游来源、路径和哈希见`基准-v1/manifest.json`。需要重做完整来源核验时：

1. 从manifest的`urls.production`下载SMT2020 ZIP，保存为`03-数据/SMT2020-official/SMT2020.zip`，解压到`03-数据/SMT2020-official/extracted/`，保留`SMT_2020 - Final/`目录结构。
2. 将SMAT2022上游仓库克隆到独立临时目录，并检出manifest的`amhs_commit`；把两份DOCX复制到`03-数据/SMAT2022/`。已跟踪工作簿无需替换。
3. 运行`.venv\Scripts\python.exe 04-研究/verify_data_baseline.py`。该既有脚本检查全部来源和派生哈希，并写入`verification.json`；不要重新生成manifest来绕过不一致。

完整来源核验还需要ZIP、AutoSched的`part.txt`和原始DOCX，它们不属于日常仿真的运行依赖。`freeze_data_baseline.py`会重建冻结产物，不作为首次安装步骤。

## 共享范围

完整ZIP、其他三个场景、第三方源码、环境和缓存不进入Git。SMAT2022目录中的嵌套`.git`也不进入本仓库；本仓库直接跟踪选定工作簿，不使用子模块。来源记录中的上游提交和说明继续保留。

`runs/`下的历史报告和回放不随仓库提供，按README命令重新生成；需要共享既有结果时应单独打包对应运行目录。当前数据共享安排不改变上游的许可状态，来源见`SMAT2022-来源记录.md`。
